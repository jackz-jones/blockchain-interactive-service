# 日志规范

> 状态：生效 | 维护者：jackz | 最后更新：2026-11-23（sop.init 填实）

## 范围

适用于本项目所有服务的运行时日志输出，包括应用日志、访问日志与审计日志（AuditLog 为 DB 落库的审计记录，非文件日志）。

## 本项目日志体系（代码事实）

- **日志库**：go-zero `logx`（`logx.MustSetup` 初始化于 `internal/svc/servicecontext.go`；全仓 58 个文件使用 `logx.Error/Info/Debug` + `logx.WithContext`）
- **输出**：file 模式，写入 `logs/`，按天切割，保留 7 天（`etc/chaininteractive.yaml` `Log` 节）
- **链路追踪**：OpenTelemetry → Jaeger（`Telemetry` 配置节，**当前 Disabled**）；指标暴露于 DevServer `:6061 /metrics`
- **审计日志**：`internal/middleware/audit.go` 自动落 `audit_logs` 表（与文件日志双轨）
- **脱敏**：`internal/validator/validator.go` 的 `MaskChainConfigSensitiveFields` / `MaskSensitiveString`（私钥前 4 后 4）；`listAPIKeysLogic.go` 的 `KeyMasked`（API Key 前 8 后 4）

## 日志等级定义

| 等级 | 语义 | 使用场景 | 生产环境是否默认开启 |
|------|------|----------|----------------------|
| `FATAL` | 不可恢复错误，进程即将退出 | 启动失败、关键依赖不可达 | ✅ |
| `ERROR` | 业务错误，需人工关注 | 数据库写入失败、外部接口异常 | ✅ |
| `WARN` | 潜在问题，暂不影响主流程 | 重试成功、降级触发、配置缺失使用默认值 | ✅ |
| `INFO` | 关键业务节点，用于生产排查 | 请求入口/出口、状态变更、定时任务执行 | ✅ |
| `DEBUG` | 开发调试细节 | 中间变量、分支走向、SQL 参数 | ❌（按需动态开启） |
| `TRACE` | 极细粒度跟踪 | 循环体内每次迭代、字节级数据 | ❌（仅本地开发） |

> **原则**：生产环境默认日志等级为 `INFO`，支持通过配置/API 动态调整至 `DEBUG` 而无需重启。

## 必须打印日志的场景

以下场景**必须**有日志输出，否则生产问题无法排查：

| # | 场景 | 最低等级 | 必须包含信息 |
|---|------|----------|--------------|
| 1 | 请求入口（API/RPC/消息消费） | `INFO` | traceId、方法名、关键入参摘要 |
| 2 | 请求出口（响应/ACK） | `INFO` | traceId、耗时、响应状态码 |
| 3 | 外部调用发起与返回（HTTP/RPC/DB/缓存） | `INFO` / `WARN` | 目标地址、耗时、状态码/错误 |
| 4 | 错误与异常捕获 | `ERROR` | 错误信息、堆栈（首次出现）、上下文参数 |
| 5 | 业务状态变更 | `INFO` | 实体ID、变更前后状态 |
| 6 | 定时/异步任务开始与结束 | `INFO` | 任务名、处理数量、耗时、成功/失败数 |
| 7 | 服务启动与关闭 | `INFO` | 版本号、配置摘要、监听地址 |
| 8 | 限流/熔断/降级触发 | `WARN` | 触发规则名、当前指标值 |
| 9 | 鉴权失败 / 权限拒绝 | `WARN` | 用户标识、目标资源、拒绝原因 |
| 10 | 重试操作 | `WARN` | 重试次数、间隔、原始错误 |

## 禁止 / 减少打印的场景

| # | 禁止/限制 | 原因 | 替代方案 |
|---|-----------|------|----------|
| 1 | **禁止**在循环体内打印 `INFO` 级别日志 | 高并发下日志量爆炸 | 使用 `DEBUG` / `TRACE`；或仅在循环结束后打印汇总 |
| 2 | **禁止**打印完整请求体/响应体（超过 1KB） | 存储成本高、可能泄露敏感数据 | 打印摘要（前 200 字符）或仅在 `DEBUG` 级别打印 |
| 3 | **禁止**打印密码、Token、密钥等敏感字段 | 安全合规 | 脱敏后输出（如 `***`）或不打印 |
| 4 | **限制**健康检查 / 心跳日志 | 高频无价值日志 | 关闭或降至 `TRACE` |
| 5 | **限制**已有监控指标覆盖的信息 | 重复信息浪费资源 | 依赖 metrics，日志仅保留异常分支 |
| 6 | **禁止**在正常分支打印 `ERROR` | 误导告警、降低信噪比 | 正常用 `INFO`/`DEBUG`，仅真实错误用 `ERROR` |
| 7 | **限制**相同错误重复打印 | 故障时日志风暴 | 采样/限速（如每分钟最多 N 条同类日志） |

## 4. Code Review 检查清单

审查日志相关代码时确认：

- [ ] 关键业务路径（§2 所列场景）是否有充足的 `INFO` 日志
- [ ] 错误分支是否有 `ERROR` 日志且包含上下文信息（错误原因、关键参数）
- [ ] 日志等级是否准确（正常流程不应为 `ERROR`）
- [ ] 是否有循环体内滥用 `INFO` / `WARN` 的情况
- [ ] 敏感信息（密码、Token、密钥、API Key、私钥）是否已脱敏或不打印（用 `Mask*` 函数，禁止手工截断）
- [ ] 脱敏值是否被误当原值回流（踩坑 `98bffb6c`，见 failures.md）
- [ ] 业务关键路径是否带 `logx.WithContext(ctx)` 传递链路上下文
- [ ] 大体量数据（请求体/响应体 >1KB）是否避免在 `INFO` 级别完整输出
- [ ] 相同错误是否有限速/采样，避免故障时日志风暴
